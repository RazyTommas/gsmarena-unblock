# Restoring the 2026-10-25 portable bundle

`mobile-observatory-2026-10-25.json` is the manifest of a 61,316,551-byte bundle
(854 devices / 94,969 observations, with `local.sqlite`, the evidence store, the
ledger, and all 16 batch inputs). The zip itself is **not beside this manifest in
git**: the box that packed it could not push anything larger than ~150 KB in one
request on 2026-10-25, so the zip travels as 128 KiB slices on the branch
`corpus-parts-2026-10-25`, one commit per slice.

## Reassemble

From the repository root, with the branch fetched:

    git checkout origin/corpus-parts-2026-10-25 -- mobile-observatory/portable/parts-2026-10-25
    ls mobile-observatory/portable/parts-2026-10-25/*.part-* | wc -l   # must print 468
    cat mobile-observatory/portable/parts-2026-10-25/mobile-observatory-2026-10-25.zip.part-* \
        > mobile-observatory/portable/mobile-observatory-2026-10-25.zip
    sha256sum mobile-observatory/portable/mobile-observatory-2026-10-25.zip
    # must print a67868ad5163321ed46e1b9bb78e573f57df28a344710a4e8b370757cc1c63e8

Fewer than 468 parts means the uploading box had not finished pushing; fetch
again later. A wrong sha256 means the same, or a corrupted part — refuse to
restore from it.

## Restore and serve

    cd mobile-observatory
    python3 run.py --bundle --restore-only --data-dir .observatory-data   # data dir must not exist yet
    PYTHONPATH=src python3 -m mobile_observatory.server --port 8000 --data-dir .observatory-data

`run.py` verifies every file in the zip against the sha256 and byte length the
manifest records, and refuses a data directory that already exists.

## A rebuild is NOT a restore

Running the batch against an empty corpus produces a valid catalogue, but not
this one: identity conclusions are remembered, and the corpus accumulates past
input versions no longer on disk. Serve the restored corpus; run the batch only
to ADD to it. This is also how the 865-device corpus of 2026-10-04 was lost on
the packing box — a rebuild replaced it, and its bundle had gone to a USB stick
instead of git. It survives only as
`/media/user/5645-9996/mobile-observatory-2026-10-04/` on that stick; if the
stick turns up, commit that zip beside `mobile-observatory-2026-10-04.json` the
same way as this one.
