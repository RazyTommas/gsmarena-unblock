Last of four probes in. This one is mostly negative but it explains the shape of the whole problem, which I think is worth more than another mirror.

THE STRUCTURAL FINDING. Every official source splits into one of two kinds, and neither can fill your column:

  BULLETIN publishers define patch levels and list CVEs, but never name a device.
    Google ASB 2026-09-01: 'Security patch levels of 2026-09-05 or later address all of these issues'
    and 'set the patch string level to: [ro.build.version.security_patch]:[2026-09-01]'.
    Occurrences of 'device model' in that bulletin: 0.
    Samsung SMR-SEP-2026: 'affected version' appears 92 times, 'affected model' 0 times,
    'patch level' 0 times. SVEs bind to Android 14/15/16/17, never to SM- codes.
    It cannot even tell you WHICH models received SMR-SEP-2026.

  DIRECTORY publishers name devices but publish commitments and end dates, never the shipped string.
    Android Enterprise Directory, Samsung Scope page, Xiaomi EOL tables.

ro.build.version.security_patch exists on-device or in firmware-distribution metadata, and nowhere else. That is exactly why samfw and fota-cloud were the natural source — and exactly why doc.samsungmobile.com works: it IS firmware-distribution metadata, published first-party by Samsung. The answer was never a cleverer way through the WAF; it was the same class of data from a host that is not fronted by one.

A DIFFERENT COLUMN, and I want to be explicit that it is different rather than let it look like a win on yours. The Android Enterprise Solutions Directory has an undocumented but plainly-constructed JSON API, robots 'Allow: /'. I verified it myself:

  GET https://androidenterprisepartners.withgoogle.com/api/search/products?aesd_product_type=Device&page_size=2
  HTTP 200, total_count: 1185
  per device: security_updates_until: 2026-12-30, receive_security_updates: TRUE,
              'Security update frequency': quarterly, 'Latest Validated OS': Android 14

I grepped the payload for security_patch, patch_level and ro.build.version. All three absent. So this is NOT an ASPL source and must not be merged into that column. What it is, is per-device end-of-security-support and cadence for 1,185 devices ACROSS ALL OEMS — which is the multi-vendor coverage your Samsung-only ASPL will never have. For a device whose support ended in 2024, 'unsupported' is a defensible exposure verdict without knowing its patch string at all. That may matter more for your non-Samsung 1,168 than the ASPL does. Caveat: AER-badged devices only, and it includes archived entries. Cursor-paged via page_token.

ALSO USEFUL, LESSER:
  security.samsungmobile.com/workScope.smsb — authoritative monthly/quarterly/biannual tiers per model,
    but marketing names only (Galaxy S26 Ultra, not SM-S938B), so it needs a name->code join.
    Static HTML, no API. Samsung's own words: support extended 'by up to 7 years' as of Jan 2024.
  Google Pixel Update Bulletins — the ONE device-bound bulletin family. Fills Pixels properly, nobody else.
  Xiaomi trust.mi.com — maps month -> 'Applicable Models', i.e. the INVERSE of what you want. Inverting it
    yields 'model X was eligible for the 2026-08 package', which is an eligibility claim, not a shipped
    patch level. My agent could not resolve the API base (two guesses 404d) and stopped rather than
    keep probing. Unconfirmed, do not count on it.
