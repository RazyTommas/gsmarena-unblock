## Android Security Bulletin Complete CVE Database

Extracted every CVE from all 124 Google Android Security Bulletins (Aug 2015 - Dec 2025). Zero extraction errors.

**5,837 CVE records.** Each mapped to:
- bulletin_month: which ASB it appeared in
- tier: 01 (Framework/System) or 05 (Kernel/vendor chipset) or 06 (rare ad-hoc)
- section: Framework, System, Kernel, Qualcomm, MediaTek, etc.
- type: EoP, RCE, ID, DoS
- severity: Critical, High, Moderate, Low
- component: specific component name
- references: A-/QC-/M- reference IDs
- updated_aosp_versions: affected Android versions

**Distribution:**
- Tier 01 (Framework+System): 2,215 CVEs (38%)
- Tier 05 (Kernel+vendor): 3,373 CVEs (58%)
- Chipset vendor total: 3,201 CVEs (55%) — Qualcomm alone is 2,439 (42%)
- Framework: 608, System: 773, MediaTek: 316, Kernel: 358

**Why this matters:** This completes the platform/framework lane of the adjudication chain. Combined with the MediaTek CVE-chipset data (which has per-chipset granularity), you now have:
1. Device → Chipset (via LineageOS/Google Play)
2. Chipset → CVE exposure (MediaTek granular, Qualcomm aggregate from ASB)
3. CVE → ASPL coverage (which bulletin month patched it)
4. Device → ASPL (via HMD/TECNO/Samsung data)

The full chain Device → Chipset → CVE → Patched-by-ASPL is now closeable for MediaTek devices. Qualcomm devices can get aggregate CVE counts per month but not per-chipset (because Google's ASB lists 'Qualcomm components' without specific chipset IDs, unlike MediaTek).
