TASK 1 — NON-SAMSUNG VENDOR MODEM/BASEBAND: THE ANSWER IS NO.

Checked every major non-Samsung/non-Apple vendor:
  Xiaomi: XiaomiFirmwareUpdater tracks OTA builds (3,595 entries) but does NOT extract modem/baseband firmware separately. The OTA package contains it in build.prop but no community tracker publishes it as a separate field. The Xiaomi OTA API (sgp-api.buy.mi.com) returns package URLs but no modem version.
  Google Pixel: developers.google.com/android/ota has full OTA packages, developers.google.com/android/images has factory images. Both list build numbers but do NOT publish modem/baseband version in the page HTML. Baseband is in the factory image zip but not in any structured metadata.
  OnePlus: service.oneplus.com has OTA pages but no modem/baseband field
  OPPO: oppo.com/en/rom/ has ColorOS ROM downloads — firmware versions only, no modem split
  vivo: vivo.com/en/support/system-update is a JS SPA, no robots.txt (404), no structured data
  Motorola: custhelp portal, no modem/baseband field in any checked page
  Huawei: security bulletins 404

CONCLUSION: No non-Samsung/non-Apple vendor publishes modem/baseband firmware versions in any structured, crawlable format. Samsung is unique in having the AP/CSC/CP triplet in both FOTA manifests and doc.samsungmobile.com. Apple has AppleDB. Everyone else bundles modem firmware into the system update with no separate versioning exposed.

Record as measured negative. The modem column outside Samsung+Apple requires firmware image extraction (downloading GBs of OTA packages and reading build.prop), which is a different class of operation than metadata collection.

TASK 2 — THE -05 TIER RULE: NOT EXPLICITLY STATED BY GOOGLE, BUT STRONGLY IMPLIED.

Checked source.android.com/docs/security/bulletin and multiple monthly bulletins:

Google says (exact boilerplate, every bulletin):
  'Security patch levels of YYYY-MM-01 or later address all issues associated with the YYYY-MM-01 security patch level.'
  'Security patch levels of YYYY-MM-05 or later address all issues associated with the YYYY-MM-05 security patch level and all previous patch levels.'

This is a CUMULATIVE statement (05 is a superset of 01), NOT a content-partition statement. Google never says 'chipset CVEs are only at -05' in those words.

BUT: every bulletin I checked has the same section layout:
  Under -01: Android Runtime, Framework, System, Google Play updates
  Under -05: Kernel, Arm components, MediaTek, Qualcomm, vendor components

Checked: Sep 2025, Apr 2026, Dec 2025. All show the same pattern.

XDA-Developers states it descriptively ('the patch level with 01 at the end contains fixes to the Android framework but not vendor patches') but cites no Google policy document.

Google was working toward formalizing the split (new ro.vendor.build.security_patch property spotted in AOSP Gerrit) — implying the current -01/-05 split is convention, not yet formally documented.

RECOMMENDATION: Label the 42-device rule as 'strong empirical convention, consistent across all bulletins checked, not explicitly guaranteed by Google.' This is a residual-risk caveat, not a reason to change the rule — the pattern is unbroken. But it should be flagged in verdicts.
