# Restoring the device-catalog runtime data (2026-10-26)

This branch carries `device-catalog-data-2026-10-26.zip` — the runtime data of
the light system ("Device Catalog — Mobile Observatory, Part 1") as it stood on
Lab2 on 2026-10-26 — split into 128 KiB slices, because it holds exactly the
values that `run.py import` + `export` + `research-seed` cannot reproduce from
the corpus alone.

**Zip:** 18,420,386 bytes, 512 files (76,253,012 bytes unpacked), sha256
`0c012cc89aa1261382ae90cc89199851258b9c4843e2adbbdf364b638afba8cd`

**Contents** (paths inside the zip):

- `catalog.sqlite` — consistent sqlite snapshot (online backup, WAL truncated)
  of `data/catalog.sqlite`. Holds the 6,776 research_facts: 498 `released_at`
  via `exact_source_parser` over gsmarena.com captures (the live `enrich` run),
  475-per-field spec facts via `restored_capture`, and 14 `chipset` +
  14 `released_at` via `llm_reviewed` apple.com/newsroom assertions.
- `evidence/` — 507 content-addressed `.bin` captures (542 capture rows in the
  db dedupe onto them by content; every research_fact's `capture_id` resolves here).
- `settings.json` — machine-local config (regions, source toggles, review
  command template). Checked: holds no secrets.
- `research/apple-assertions.json` — the reviewed assertion file behind the 14
  `llm_reviewed` facts.

## Reassemble

From the repository root, with this branch fetched:

    git checkout origin/catalog-parts-2026-10-26 -- device-catalog/portable/parts-2026-10-26
    ls device-catalog/portable/parts-2026-10-26/*.part-* | wc -l   # must print 141
    cat device-catalog/portable/parts-2026-10-26/device-catalog-data-2026-10-26.zip.part-* \
        > device-catalog-data-2026-10-26.zip
    sha256sum device-catalog-data-2026-10-26.zip
    # must print 0c012cc89aa1261382ae90cc89199851258b9c4843e2adbbdf364b638afba8cd

Fewer than 141 parts means the uploading box had not finished pushing; fetch
again later. A wrong sha256 means the same, or a corrupted part — refuse to
restore from it.

## Restore

Unpack into the checked-out light system's `data/` directory (branch
`feat/device-catalog`), which must not already hold a populated catalog:

    cd device-catalog
    mkdir -p data
    unzip ../device-catalog-data-2026-10-26.zip -d data
    python3 run.py status   # expect devices 2335 / models 854 / firmwares 78401

`settings.json` was Lab2's; adjust `command` and source toggles to the local
box rather than inheriting them blindly.

## A rebuild is NOT a restore

`run.py import <corpus>` + `run.py export` rebuilds the catalog from the
corpus, but the enrich/research values (release dates, Apple chipsets, spec
fields) rest on captures and reviewed assertions that only this evidence store
holds. Re-fetching them produces a different catalog, not this one. Restore
this data; run import only against an empty catalog, and enrich only to ADD.
